# 資料更新說明（給非工程人員）

所有步驟都可以直接在 GitHub 網頁上完成，不需要安裝任何軟體。

每次存檔（commit）到 `main` 後：

1. GitHub 會自動檢查資料。
2. 檢查通過就重新發布網站，約 1–2 分鐘完成。
3. 到 repo 上方的 **Actions** 分頁可以看進度：綠色勾勾代表已更新，紅色叉叉代表資料有問題、網站**維持舊版**不受影響。

---

## 一、型錄改版：替換整份資料庫

1. 進入 `data/source/`，點 `products-db.json`。
2. 點右上角「⋯」→ **Upload files**（或直接把新檔案拖進 `data/source/` 資料夾頁面）。
3. 上傳新版檔案，**檔名必須是 `products-db.json`**。
4. 下方填一句說明（例如「2027 型錄改版」），按 **Commit changes**。
5. 到 **Actions** 確認變成綠色勾勾。

新資料庫的格式要跟現在這份相同：最外層有 `products` 陣列，每筆至少有 `model`、`product_name`、`catalog_section`、`record_type`。

## 一之二、官網資料更新：替換官網資料庫

網站規格以**舞光官網資料為主**，官網沒有的型號或欄位（例如牌價、型錄頁碼）才用型錄資料。

1. 進入 `data/source/`，上傳新版官網資料，**檔名必須是 `official-db.json`**。
2. Commit，等 Actions 出現綠色勾勾。

官網資料的格式要跟現在這份相同：最外層有 `products` 陣列，每筆有 `model`、`name`、`category.name`、`specs`、`images.main`、`source_url`。

型錄與官網數值不同時，網站一律採用官網；每次建置的檢查報告（`data-report`）會列出所有不一致的型號與欄位，方便回頭核對型錄。

官網新增的產品會自動加入網站，條件是它屬於 `data/categories.config.json` 裡 `officialCategories` 列出的官網分類；這些產品沒有牌價，顯示「未列價」。

## 二、修正單一型號的數值

發現某個型號的數值錯誤，但不想等型錄改版時：

1. 打開 `data/corrections.json`，點鉛筆圖示編輯。
2. 照現有格式加一筆，例如：

   ```json
   { "model": "D-CEX45NSW", "field": "luminous_flux_lm", "from": null, "to": 4000, "note": "依官網修正" }
   ```

   - `model`：型號
   - `field`：欄位名稱，常用的有
     - `power_w`：瓦數
     - `luminous_flux_lm`：光通量
     - `color_temperature_k`：色溫
     - `cri_ra`：演色性
     - `beam_angle_deg`：發光角度
     - `cutout`：開孔，例如 `"9.5cm"`
     - `list_price`：牌價
   - `from`：資料庫原本的值（不知道可以不寫）
   - `to`：正確的值；寫 `null` 代表先不顯示
   - `note`：備註
3. Commit。網站上修正過的數值旁會出現 †。

型錄改版後，如果新資料已經改對了，資料檢查報告會提醒「這筆修正可以刪除」。

## 三、新增或更換產品圖片

產品圖片預設使用官網資料裡的圖片網址。只有官網沒有圖、或想換成別張圖的型號，才需要這一步。

1. 打開 `data/images.csv`（第一次請新增這個檔案），一行一個型號：

   ```
   型號,網址
   D-9DOB9N,https://www.example.com/images/D-9DOB9N.jpg
   ```

2. Commit。沒有圖片的型號會顯示類別示意圖。

## 四、指定熱門比較

空的比較頁下方的「熱門比較」預設自動產生。想指定常用組合時，編輯 `data/featured.json`：

```json
[
  { "category": "downlight", "title": "9.5cm 崁燈人氣三款", "models": ["D-9DOB9N", "D-9DOV9N", "D-9DOHU8NR3"] }
]
```

`category` 的值：

| 值 | 類別 |
|---|---|
| `downlight` | 崁燈 |
| `can` | 筒燈 |
| `track` | 投射燈/軌道燈 |
| `panel` | 平板燈 |
| `ceiling` | 吸頂燈 |
| `strip` | 軟條燈 |

## 五、增減類別

編輯 `data/categories.config.json`。每個類別可以用三種方式對應到資料庫：

- 型錄分類名稱（`sections`）
- 品名關鍵字（`nameIncludes`）
- 官網分類名稱（`officialCategories`，例如 `"一體化崁燈"`）

例如加入壁燈：

```json
{ "id": "wall", "label": "壁燈", "icon": "ceiling", "sections": ["壁燈"], "officialCategories": ["室內壁燈/床頭燈", "戶外防水壁燈"] }
```

## 發布失敗怎麼辦

1. 到 **Actions**，點紅色叉叉那一次。
2. 展開「檢查資料並建置」，會列出原因，例如「型號重複：D-XXXX」「第 12 筆缺少必要欄位 model」。
3. 修正後再 commit 一次即可。修好之前，網站維持上一個正常的版本。

每次建置的完整檢查報告（可疑數值、缺圖型號清單）可以在同一頁最下方的 **Artifacts → data-report** 下載。
