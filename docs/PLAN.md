# 燈具規格快速比較表：實作計劃（v2，所有問題已確認）

> 狀態：**M1–M6 全部完成，網站已上線** https://kuperss.github.io/lighting-comparison-tool/
> 計劃之後的變更（官網資料整合、品牌配色、Logo）記錄在上層的 `AGENTS.md`。

---

## 1. 目標

做一個公開網站，讓一般消費者、設計師、水電工程商、經銷商與業務，**在同一類燈具中一次比較最多 4 款**的規格，操作方式參考 Apple 官網的機型比較。

- 桌機與手機並重
- 型錄改版時，**換掉一份 JSON 就能更新整個網站**
- 放在 GitHub Pages，免費、免主機、免資料庫

## 2. 已確定的決策

| 項目 | 決定 |

## 3. 資料架構與更新流程

### 3.1 檔案

```
data/
  source/products-db.json      ← 型錄資料庫（改版時整份替換）
  images.json / images.csv     ← 型號 → 官網圖片網址（你提供）
  categories.config.json       ← 類別與型錄分類的對應（可改，不需要寫程式）
  corrections.json             ← 人工修正（見 3.6），改版後仍會套用
  featured.json                ← 指定的熱門比較（選填）
scripts/build-data.mjs         ← 驗證 + 轉換
src/data/catalog.json          ← 產出檔（自動產生，不手改）
```

### 3.2 類別對應設定（範例）

```json
[
  { "id": "downlight", "label": "崁燈",          "sections": ["崁燈"] },
  { "id": "can",       "label": "筒燈",          "sections": ["筒燈"] },
  { "id": "track",     "label": "投射燈/軌道燈", "sections": ["軌道燈具系統"] },
  { "id": "panel",     "label": "平板燈",        "nameIncludes": ["平板"] },
  { "id": "ceiling",   "label": "吸頂燈",        "sections": ["單色與調光調色吸頂燈"] },
  { "id": "strip",     "label": "軟條燈",        "sections": ["軟條燈與霓虹軟條燈"] }
]
```

以後要新增「壁燈」「支架燈」等類別，只要在這個檔案加一行。

### 3.3 建置時的自動檢查（沒通過就不發布）

- JSON 格式與必要欄位是否齊全（model、product_name、catalog_section 等）
- 型號是否重複
- 每個類別至少有 2 個機型
- 產出**資料檢查報告**，列出可疑數值（例如同一機型各色溫的瓦數差很多），但不擋發布
- 列出沒有圖片網址的型號

### 3.4 型錄改版時的更新步驟

1. 用新版 JSON 取代 `data/source/products-db.json`（檔名固定）
2. 若有新型號，更新圖片對照檔
3. 在 GitHub 網頁上 commit，或用 git 推上去 → GitHub Actions 自動檢查、建置並發布，約 1–2 分鐘

頁尾會顯示「資料版本 1.0.0 · 驗證日期 2026-09-23」，方便確認網站上的是哪一版。

### 3.5 機型分組規則

型錄裡同一款燈常有多個 SKU，只差色溫或燈體顏色。例如：

- 神盾吸頂筒燈 10W 有 6 個 SKU（3000 / 4000 / 6000K，白 / 黑）

網站把它們合成一個「機型」：

- 比較欄選的是**機型**
- 欄內用色溫圓點與顏色切換到該 SKU，規格數字跟著變

分組方式：同系列、型號只差色溫字母（W/N/D）或外觀字尾（-BK 黑、-WH 白、-LW 木紋）的 SKU，視為同一機型。

目前結果：

| 類別 | 機型數 | SKU 數 |
|---|---|---|
| 崁燈 | 72 | 220 |
| 筒燈 | 4 | 24 |
| 投射燈/軌道燈 | 48 | 176 |
| 平板燈 | 3 | 6 |
| 吸頂燈 | 8 | 22 |
| 軟條燈 | 27 | 67 |

### 3.6 人工修正（corrections.json）

資料庫有錯時，不必等型錄改版，也不用直接改原始 JSON：

- 把修正寫在 `corrections.json`，建置時自動套用，網站顯示修正後的值，並標示「已人工修正」。
- 換上新版資料庫後，如果新資料已經跟修正值相同，檢查報告會提示「這筆修正可以刪除」；如果新資料的值又不一樣，會提示你確認。

目前已知的修正（你已確認）：

| 型號 | 欄位 | 資料庫原值 | 修正為 | 光通量 |
|---|---|---|---|---|
| D-CEX45NSW 雪晴 4000K | 瓦數 | 3W | **45W** | 原值 30lm 不可信，先顯示「—」，待佐證資料 |
| D-CEC24DSW-LW 嫦娥 | 瓦數 | 2W | **24W** | 原值 150lm 不可信，先顯示「—」，待佐證資料 |
| D-CEC24DSW 嫦娥 | 瓦數 | 空 | **24W** | 空，待佐證資料 |
| D-CEC24NSW-LW 嫦娥 | 瓦數 | 空 | **24W** | 空，待佐證資料 |

你之後提供的佐證資料，我會拿來核對，並補齊上表的光通量。

## 4. 規格列（依你的清單，並對照資料庫實際有的欄位）

| 分組 | 規格 | 資料來源 | 備註 |
|---|---|---|---|
| 光源 | 瓦數 | power_w；軟條燈用每米瓦數 | |
| | 光通量 / 光效 | luminous_flux_lm、efficacy_lm_w | 沒有光效者以 lm÷W 換算，標「換算」 |
| | 色溫 | color_temperature_k | 用色點顯示；三段調色、可調色溫用色條 |
| | 演色性 | cri_ra、r9_min | |
| | 發光角度 | beam_angle_deg | 光錐圖＋換算光斑；超過 180° 只畫光型 |
| 安裝 | 開孔 / 尺寸 / 長度 | cutout、body_size、length | 依類別顯示適用的欄位 |
| | 輸入電壓 | input_voltage | 軟條燈需另購驅動器，會標示 |
| | 材質 | material | |
| 功能 | 調光 / 控制 | 品名中明確寫出的「調光、調色、壁切、DALI、撥碼、感應」 | 型錄沒有獨立欄位，只依品名整理 |
| | 防水等級 | ip_rating | 目前只有軟條燈有資料 |
| 認證 | 商品檢驗 / NCC | certifications | |
| | 節能標章 | 品名含「節標」 | |
| | 壽命 / 保固 | **資料庫沒有** | 整列隱藏，資料補上後自動出現 |
| 價格 | 牌價 | list_price | 依 SKU 顯示 |
| 參考 | 型錄頁碼、型號 | catalog_page、model | |

- 全部機型都沒有值的列會自動隱藏。
- 開啟「只顯示差異」時，隱藏數值相同的列。

## 5. 畫面與功能

| 畫面 | 方案 | 重點 |
|---|---|---|
| 首頁 / 選類別 | 2i | 類別卡片，同類別最多比 4 款 |
| 空的比較頁 | 2j | 4 個空欄，加上「熱門比較」一鍵帶入（依資料自動產生，例如同系列不同開孔） |
| 比較頁（桌機） | 2a＋2b | 4 欄並排，每欄可換機型；色溫切換；往下捲時頂部出現吸頂機型列；規格分組收合；「只顯示差異」會把有差異的列上色；光束圖 |
| 機型選擇器 | 2c | 欄位下拉，鎖定目前類別；可搜尋型號、品名、瓦數；依系列分組；標出「已在第 N 欄」；可從比較中移除 |
| 手機比較 | 2e | 上方固定 4 個縮圖，點選 2 款並排；分組手風琴；只看差異 |
| 產品列表（桌機） | 2g | 依類別列出機型卡片，勾選「比較」；底部比較匣 4 格 |
| 產品列表（手機） | 2h | 浮動比較鈕，點開底部抽屜 |

### 5.1 分享、複製、列印

- **分享連結**：比較狀態寫在網址裡（例如 `?c=downlight&m=D-9DOB9N,D-12DOB12N`），貼給別人打開就是同一個比較。
- **複製比較清單**：複製成純文字，方便貼到 LINE 或 Email，例如：

  ```
  崁燈比較
  1. 波爾防眩崁燈 9.5cm 9W（D-9DOB9N 4000K）牌價 $xxx
  2. …
  連結：https://…
  ```

- **列印 / 匯出 PDF**：專用列印版面（白底、全部分組展開、附網址與資料版本），用瀏覽器的「另存為 PDF」。

### 5.2 圖片

- 從你的對照檔取官網圖片網址，用 `<img>` 直接載入，不經過自己的伺服器。
- 有些網站會擋外部連結圖片，所以會加上 `referrerpolicy="no-referrer"`。
- 載入失敗時改顯示類別示意圖。

## 6. 技術細節

- React + Vite，不需要後端
- 用網址參數保存狀態，避免 GitHub Pages 重新整理時出現 404
- GitHub Actions：推到 main → 建置資料 → 建置網站 → 發布到 Pages
- 字型：Noto Sans TC（Google Fonts）
- 無障礙：鍵盤可操作、焦點清楚、對比足夠

### 測試

- 資料轉換單元測試：分組、欄位整理、檢查規則
- 瀏覽器自動測試：桌機與手機兩種寬度，走完「選類別 → 加入 4 款 → 只顯示差異 → 分享連結還原」
